# 022 — Používateľská cesta a konverzia

Use when a visitor can admire the site but cannot confidently complete its purpose. Define conversion by a real outcome rather than animation completion.

## Decide

Choose a primary action and the evidence needed before it. Distinguish intent, submission, accepted operation and fulfilled service. Decide which steps are essential and which are avoidable friction. Respect the user's autonomy; clarity is more durable than deceptive urgency.

## Execute

Map entry, orientation, evaluation, action, confirmation and recovery. At each step identify unanswered questions, data required, external transitions and failure behavior. Place actions where the visitor has enough information, with labels that predict the next step. Preserve entered data when recoverable errors occur.

Use animation to connect states or explain progress without delaying the operation. Keep an external booking link straightforward when no provider integration is available. For a multi-step flow, define return/back behavior, validation timing and how the user edits an earlier choice. Avoid decorative steps that exist only to showcase motion.

## Verify

Complete the journey from a cold load, direct link and mobile viewport. Exercise one realistic interruption or rejection. Confirm that apparent success follows an authoritative response and that a second click cannot accidentally duplicate a consequential operation. Inspect whether the UI still works with decoration disabled.

## Deliver

Provide the journey map, actual destinations, state model, event meanings and observed checks. Report friction and uncertainty as findings, not unmeasured conversion uplift. If comparing alternatives, define the behavioral hypothesis and evidence needed before declaring a winner.
