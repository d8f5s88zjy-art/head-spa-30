# 087 — Výkonnostné rozpočty a regresie

Use when cinematic ambition must fit device, loading or operating constraints. Budgets are explicit project decisions backed by observation.

## Decide

Choose budgets for the useful first view, interaction responsiveness, media transfer, retained memory and runtime work that matter to the project. Tie each to a user/device scenario. Do not use one universal megabyte or frame-rate limit as proof of quality.

## Execute

Record a baseline with the actual build and conditions. Assign costs to the signature scene, fonts, third-party code and media. Prefer early limits that force a useful tradeoff over late compression of everything. Separate nominal decoded estimates from measured browser/GPU behavior.

Add a regression gate only where it catches a meaningful recurring risk. Use comparable runs and tolerate normal measurement variance explicitly. When over budget, diagnose the bottleneck and choose the least damaging simplification: fewer passes, lower resolution, bounded decode window or a static alternative.

## Verify

Compare the changed experience under the same conditions and check functionality/appearance after optimization. Review cold/warm paths and the primary interaction. Do not claim a device result from emulation without naming that limitation. Avoid broad repeated benchmarks after the actual risk is resolved.

## Deliver

Provide budgets, rationale, observed measurements, tradeoffs and accepted exceptions with owner. Make the next developer able to reproduce the useful check. A budget spreadsheet without real traces or observations is a planning artifact, not performance validation.
