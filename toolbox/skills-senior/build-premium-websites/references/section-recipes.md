# 027 — Kompozície jednotlivých sekcií

These are original compositional starting points, not universal templates. Each section must answer a different visitor question. Keep real content in semantic DOM; decoration may fail independently.

| Section | Composition and evidence | Motion purpose | Mobile and failure behavior | Acceptance observation |
|---|---|---|---|---|
| Hero | One dominant authentic subject; offer, location/context and primary action beside the focal area | Short arrival establishing hierarchy | Recompose crop; offer/action visible before media loads | Visitor can identify offer and use action without waiting |
| Service choice | Scannable rows or grouped options with real name, duration, price and scope | Optional selection continuity | Long names wrap; prices remain associated; touch selection | An option can be understood and selected without hover |
| Process | Wide context, detail, result; each image tied to a factual step | Matching framing or occlusion connects related steps | Normal document flow if pinning reduces reading space | Step labels agree with visible media and reverse scroll |
| Proof | Real work and attributable context; avoid invented customer numbers | Gentle transition between evidence items | Accessible gallery controls and still image fallback | Attribution/claim verified; images load and fit |
| Team | Portrait with role and relevant verified experience; vary scale only for actual hierarchy | Brief reveal; no mandatory carousel | Name/role not over low-contrast face area | Missing photo and longer bio leave usable layout |
| Space/location | Real venue image with address, opening/contact information when verified | A restrained spatial move only if actual source supports it | Static photo and real directions link | Location info does not depend on an embedded map |
| Product inspection | Object plus stable specification and variant UI | Real angle/variant inspection | Poster and variant controls if 3D fails | Selected variant, price and order data stay consistent |
| Comparison/pricing | Comparable attributes aligned; explicit inclusions and conditions | Selection feedback, no moving prices | Stack with repeated labels or usable table scroll region | Currency and units consistent; no false default scarcity |
| FAQ | Question-led semantic disclosure with useful answers | Small state change if helpful | Keyboard-operable, height based on content | Answer opens; expanded state exposed; focus retained |
| Booking/contact | Short decision recap; real destination; practical next-step details | Settle into stable composition | Link/button reachable with keyboard and one hand | Correct destination; server failures do not show fake success |
| Footer | Navigation, real contact and applicable information | Usually no motion | Clear hierarchy, no overlapping sticky layers | No dead policy/contact links or invented legal claims |
| Empty/error state | Explain actual condition and recovery | Optional subtle state continuity | Same recovery available without canvas/network success | Retrying does not duplicate a transaction |

For every chosen section write: question → truthful content → dominant relationship → action → stable state → transition → responsive alternative → failure. Do not create a section solely to display a technique.

## Example composition contract

For a fictional local craft studio with 12 supplied photos and external booking: use one strong landscape as the opening, two narrow close-ups as process punctuation, a calm three-image proof sequence, then service rows and the booking action. Use a shared vertical crop boundary as the signature motif. On a narrow phone, place the offer above the image and use normal flow. This describes a design possibility, not a claim about any real studio's photos or services.

For a product whose shape matters: keep specifications and variant selection stable while the viewer changes angle. Connect the model's material ID to the actual SKU map. A cinematic camera reveal must yield to user control and must not reset a chosen variant when replayed.

## Component handoff fields

Record semantic element, data inputs, required/optional content, maximum expected copy, interactive states, keyboard behavior, fallback, motion owner and cleanup. Prefer a small coherent vocabulary of reusable components. Keep art-directed one-off composition at the section level rather than contaminating every button with special behavior.

## Senior decision gate

- **Decision:** Match layout to the information a section must communicate.
- **Deliverable:** Content-specific responsive sections.
- **Verification:** Check long text, missing optional media and actual CTA destination.
