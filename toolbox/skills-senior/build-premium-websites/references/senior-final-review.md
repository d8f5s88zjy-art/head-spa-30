# 100 — Záverečná seniorská kontrola

Use before declaring an authorized task complete. Review the outcome against its actual scope rather than performing every possible check.

## Decide

Identify the user-visible result, critical invariants and relevant acceptance evidence. For a small edit inspect the affected path; for a full release review the complete primary journey and material boundaries. Treat visual quality, functionality, truth and operability as separate requirements.

## Execute

Read the final diff/artifact and compare it with the latest user request. Check for invented business facts, unfinished placeholders, inaccessible primary controls, fake success and missing cleanup. Remove unused experiments and keep the delivery focused. Confirm that developer notes describe actual behavior and actual commands.

Review source and test claims: distinguish observed, mocked, estimated, code-reviewed, blocked and not run. A consistent evidence ledger does not authenticate a human observation or certify the website. Keep unresolved material limitations visible. Complete saving through the applicable workflow; a local write is not proof of successful remote persistence.

## Verify

Run only the remaining checks needed to resolve concrete risks. Confirm the main task still works after final corrections. For publication, inspect the authorized deployed version when accessible. Stop optional polishing once scope and meaningful evidence are sufficient; do not substitute more chapters, tools or tests for a working result.

## Deliver

Lead with what is complete, explain the key decision briefly, state verification and remaining material limits. Give the actual review/live artifact where appropriate. Never promise universal senior expertise, guaranteed price, a measured quality multiplier or hidden ongoing learning from the existence of this skill.
